Plugin API

A plugin lets another program post messages into a group chat. For example, a build server can announce that a build finished, or a monitoring script can report an alert.

1. Create a plugin

  1. Open the group and click Edit. You need to be the group owner or an admin.
  2. Open the Plugins tab, enter a name (2 to 30 letters, digits, spaces, _ or -), and click Create plugin.
  3. Copy the key that appears. It is shown only once. If you lose it, delete the plugin and create a new one.

Deleting a plugin in the same tab revokes its key straight away.

2. Authenticate

Send the key in the X-Plugin-Key header with every request:

X-Plugin-Key: sc_your_key_here

3. Endpoints

The base address is the address of your Spring Chat server, for example http://localhost:8080.

GET /api/plugin/info

Checks the key and shows which plugin and group it belongs to.

curl -H "X-Plugin-Key: sc_your_key_here" http://localhost:8080/api/plugin/info
{
  "name": "Build Bot",
  "groupId": "3f2a9c1e-...",
  "group": "Release team"
}

POST /api/plugin/messages

Posts a text message into the group. The body is JSON with a text field of up to 2000 characters.

curl -X POST http://localhost:8080/api/plugin/messages \
  -H "X-Plugin-Key: sc_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"text": "Build 412 finished successfully."}'

The response is the stored message:

{
  "id": "8d1c...",
  "roomId": "group-3f2a9c1e-...",
  "sender": "(plugin) Build Bot",
  "type": "TEXT",
  "content": "Build 412 finished successfully.",
  "timestamp": 1761560000000
}

Example in JavaScript

const res = await fetch("http://localhost:8080/api/plugin/messages", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Plugin-Key": process.env.CHAT_PLUGIN_KEY
  },
  body: JSON.stringify({ text: "Deploy to staging complete." })
});
if (!res.ok) throw new Error(await res.text());

Example in Java

This example uses the built-in java.net.http client, which is available in Java 11 and newer, so it needs no extra libraries. Set CHAT_PLUGIN_KEY in your environment before you run it.

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class PluginExample {

    public static void main(String[] args) throws Exception {
        String key = System.getenv("CHAT_PLUGIN_KEY");
        String body = "{\"text\": \"Deploy to staging complete.\"}";

        HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create("http://localhost:8080/api/plugin/messages"))
                .header("Content-Type", "application/json")
                .header("X-Plugin-Key", key)
                .POST(HttpRequest.BodyPublishers.ofString(body))
                .build();

        HttpResponse<String> response = HttpClient.newHttpClient()
                .send(request, HttpResponse.BodyHandlers.ofString());

        if (response.statusCode() != 200) {
            throw new IllegalStateException("Post failed: " + response.statusCode() + " " + response.body());
        }
        System.out.println("Posted: " + response.body());
    }
}

Example in CommonJS (.cjs)

Use this with require(). It needs Node.js 18 or newer for the built-in fetch. Save the file as post-message.cjs.

// post-message.cjs
// Run with: CHAT_PLUGIN_KEY=sc_your_key_here node post-message.cjs
const key = process.env.CHAT_PLUGIN_KEY;

async function postMessage(text) {
  const res = await fetch("http://localhost:8080/api/plugin/messages", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-Plugin-Key": key
    },
    body: JSON.stringify({ text })
  });
  if (!res.ok) {
    throw new Error(`Post failed: ${res.status} ${await res.text()}`);
  }
  return res.json();
}

postMessage("Deploy to staging complete.")
  .then((message) => console.log("Posted:", message.id))
  .catch((err) => {
    console.error(err.message);
    process.exitCode = 1;
  });

module.exports = { postMessage };

Example in ES modules (.mjs)

Module: @springchat/api for ES modules (.mjs)

The @springchat/api module works with import and with require(). It is in the clients/springchat-api folder of the project. Install it from that folder with:

npm install ./clients/springchat-api

Then use it in an ES module:

import { SpringChatPlugin } from "@springchat/api";

const plugin = new SpringChatPlugin({
  baseUrl: "http://localhost:8080",
  key: process.env.CHAT_PLUGIN_KEY
});

const message = await plugin.postMessage("Deploy to staging complete.");
console.log("Posted:", message.id);

const info = await plugin.info();
console.log("Plugin:", info.name, "in", info.group);

Errors from the server are thrown as SpringChatError, which has a status property.

Module: spring.chat.api for Java

The Java client is the package spring.chat.api. It is in the clients/java/spring/chat/api folder of the project. Copy that folder into your source tree at src/main/java/spring/chat/api/, or compile it into a JAR. It needs Java 11 or newer and uses the built-in java.net.http client.

import spring.chat.api.SpringChatPlugin;

public class Deploy {

    public static void main(String[] args) throws Exception {
        SpringChatPlugin plugin = new SpringChatPlugin("http://localhost:8080", System.getenv("CHAT_PLUGIN_KEY"));
        String reply = plugin.postMessage("Deploy to staging complete.");
        System.out.println("Posted: " + reply);
    }
}

Server errors are thrown as SpringChatPlugin.ApiException, which has a status() method.

Note: These modules are part of this project. They are not yet published to npm or Maven Central, so install them from the project folder as shown above.

4. Messages from plugins

  • Messages appear as (plugin) Name, so members can tell them apart from people.
  • Plugins can post even when the group is set to Only admins can send messages, because the key belongs to an admin-created plugin.
  • Posts appear live for everyone who has the group open.

5. Errors

StatusMeaning
400The text is empty or longer than 2000 characters.
401The X-Plugin-Key header is missing, wrong, or belongs to a deleted plugin.

6. Good practice

  • Keep keys out of source code. Store them in environment variables or a secrets manager.
  • Create one plugin per script or service, so you can revoke one without affecting the others.
  • Post short, useful messages. Long logs are better shared as a file.

7. Full examples

Each example below is a complete file. They use the @springchat/api module from section 3, so install it first with npm install ./clients/springchat-api. Set CHAT_PLUGIN_KEY to your key before you run them.

Custom command: chatctl

A command-line tool that posts deploy, build, and alert messages to the group. Save the file as chatctl.mjs.

// chatctl.mjs - a command-line tool that posts to a Spring Chat group
// Usage:
//   CHAT_PLUGIN_KEY=sc_your_key_here node chatctl.mjs deploy staging v1.4.2
//   CHAT_PLUGIN_KEY=sc_your_key_here node chatctl.mjs build 412 success
//   CHAT_PLUGIN_KEY=sc_your_key_here node chatctl.mjs alert Disk is 90% full
//   node chatctl.mjs help
import { SpringChatPlugin, SpringChatError } from "@springchat/api";

const COMMANDS = {
  deploy: {
    usage: "deploy <environment> <version>",
    minArgs: 2,
    format: ([environment, version]) => `Deploy to ${environment} started: ${version}`
  },
  build: {
    usage: "build <number> <success|failed>",
    minArgs: 2,
    format: ([number, status]) => `Build #${number} ${status}.`
  },
  alert: {
    usage: "alert <message...>",
    minArgs: 1,
    format: (words) => `ALERT: ${words.join(" ")}`
  }
};

function printHelp() {
  console.log("Commands:");
  for (const command of Object.values(COMMANDS)) console.log(`  ${command.usage}`);
  console.log("  help");
}

async function run(argv) {
  const [name, ...args] = argv;
  if (!name || name === "help") {
    printHelp();
    return;
  }

  const command = COMMANDS[name];
  if (!command) throw new Error(`Unknown command "${name}". Run "help" for the list.`);
  if (args.length < command.minArgs) throw new Error(`Usage: ${command.usage}`);

  const plugin = new SpringChatPlugin({
    baseUrl: process.env.CHAT_URL || "http://localhost:8080",
    key: process.env.CHAT_PLUGIN_KEY
  });
  const message = await plugin.postMessage(command.format(args));
  console.log(`Posted: ${message.content}`);
}

run(process.argv.slice(2)).catch((err) => {
  console.error(err instanceof SpringChatError
    ? `Server error ${err.status}: ${err.message}`
    : err.message);
  process.exitCode = 1;
});

CHAT_PLUGIN_KEY=sc_your_key_here node chatctl.mjs alert Disk is 90 percent full

Custom UI: status cards

A small formatter that turns status data into a structured message: a heading line with the status in brackets, then one labeled field per line. Chat bubbles show plain text, so the layout uses line breaks rather than tables. Save the file as card.mjs, then post its output with postMessage.

// card.mjs - a custom layout for status messages
// Builds a short, structured message: a heading line, then one labeled field per line.
export function statusCard({ title, status, fields = {} }) {
  const lines = [`[${status.toUpperCase()}] ${title}`];
  for (const [label, value] of Object.entries(fields)) {
    lines.push(`  ${label}: ${value}`);
  }
  return lines.join("\n");
}
import { SpringChatPlugin } from "@springchat/api";
import { statusCard } from "./card.mjs";

const plugin = new SpringChatPlugin({ key: process.env.CHAT_PLUGIN_KEY });
const text = statusCard({
  title: "Build #412",
  status: "success",
  fields: { Branch: "main", Duration: "3m 12s" }
});
await plugin.postMessage(text);

Custom verify: checked posting

A wrapper that checks the key and group before posting, blocks empty, overly long, or secret-looking text, and confirms the server stored the same text from this plugin. Save the file as verify.mjs. Set CHAT_GROUP to a group name to make sure the key belongs to that group.

// verify.mjs - checks the key, the group and the text before posting, then checks the server's reply
import { SpringChatPlugin, SpringChatError } from "@springchat/api";

const MAX_LENGTH = 2000;
const SECRET_PATTERNS = [
  /sc_[a-f0-9]{16,}/i,                              // a plugin key
  /password\s*[=:]/i,                               // a password assignment
  /-----BEGIN [A-Z ]*PRIVATE KEY-----/              // a private key
];

// Rejects text that is empty, too long, or looks like it contains a secret
export function checkText(text) {
  if (typeof text !== "string" || text.trim() === "") throw new Error("Message is empty");
  if (text.length > MAX_LENGTH) throw new Error(`Message is longer than ${MAX_LENGTH} characters`);
  for (const pattern of SECRET_PATTERNS) {
    if (pattern.test(text)) throw new Error("Message looks like it contains a secret, so it was not sent");
  }
  return text.trim();
}

// Asks the server who this key belongs to. An invalid key throws a 401 SpringChatError.
export async function verifyKey(plugin, expectedGroup) {
  const info = await plugin.info();
  if (expectedGroup && info.group !== expectedGroup) {
    throw new Error(`This key belongs to "${info.group}", not "${expectedGroup}"`);
  }
  return info;
}

// Checks the key and text, posts the message, and confirms the server stored what was sent
export async function sendVerified(plugin, text, expectedGroup) {
  const clean = checkText(text);
  const info = await verifyKey(plugin, expectedGroup);
  const message = await plugin.postMessage(clean);

  if (message.content !== clean) throw new Error("The server stored different text from what was sent");
  if (message.sender !== `(plugin) ${info.name}`) throw new Error("The message was not posted by this plugin");
  return message;
}

// Example use
const plugin = new SpringChatPlugin({ key: process.env.CHAT_PLUGIN_KEY });
sendVerified(plugin, "Deploy to staging complete.", process.env.CHAT_GROUP || null)
  .then((message) => console.log("Verified and posted:", message.id))
  .catch((err) => {
    if (err instanceof SpringChatError) {
      console.error(`Server rejected the request (${err.status}): ${err.message}`);
    } else {
      console.error(err.message);
    }
    process.exitCode = 1;
  });
CHAT_PLUGIN_KEY=sc_your_key_here CHAT_GROUP="Release team" node verify.mjs

The examples only send messages. The Plugin API does not yet deliver chat messages or commands to a plugin, so a "command" here means a command you run in a terminal.

Note: Keys are stored on the server only as a hash. The current app keeps all data in memory, so plugins and keys are lost when the server restarts. Create them again after a restart.
